CASE-02

Real-Time Stock Analytics Platform

System / Business Analyst · Nov 2025–Feb 2026 · Microservices

A real-time stock analytics platform for individual investors, modeled end to end with UML — use case, activity, sequence, class, and state diagrams — before a line of the microservices backend was written.

01Problem Statement

Real-time data doesn't fit in a monolith

Individual investors need accurate, up-to-the-minute market data — but traditional monolithic platforms struggle to process high-frequency stock data at low latency. As data volume grows, a tightly coupled system can't scale one bottlenecked part without scaling the whole application.

Who it's for

  • Individual investors — tracking portfolios and researching stocks without institutional-grade tools.
  • Registered users — need real-time price updates, historical data, and community insight in one place.
02As-Is Analysis

Why the existing approach breaks down

Analysis of traditional monolithic market-data systems surfaced four recurring pain points that directly shaped the to-be architecture:

Identified pain points

  • Scalability — scaling means scaling the entire application, even when only data ingestion needs more capacity.
  • Real-time processing — batch-oriented systems can't keep up with continuous, high-frequency market data.
  • Maintenance & upgrades — tightly coupled modules mean small changes risk breaking the whole platform, often with downtime.
  • Integrating new data sources — adding a new market data provider requires touching multiple components at once.
Each of these maps directly to a to-be decision: independent services instead of one deployable, a streaming pipeline (Kafka + Redis) instead of batch jobs, and a Gateway service that isolates the WebSocket layer from REST traffic.
03To-Be Solution

Five services, one real-time pipeline

The platform ingests live market data over WebSocket, streams it through Kafka, and serves both real-time and historical views without any one service becoming a bottleneck:

Services

  • Market Ingest Service (Python) — entry point of the pipeline, converts the raw Alpaca WebSocket feed into structured events.
  • Market Stream Service (Python) — transforms and enriches data for both storage and real-time delivery via Redis Streams.
  • Market API Service (Python) — serves structured historical and financial data from PostgreSQL.
  • Gateway Service (Express.js) — routes REST requests and broadcasts real-time events over WebSocket, isolated from the data-processing services.
  • Frontend (Next.js) — dashboard, portfolio tracking, stock research, and community discussion.
Stack: Next.js · Express.js Gateway · Python microservices · Kafka · Redis Streams · PostgreSQL · WebSocket

04User Stories & Acceptance Criteria

From the use case model

Requirements were modeled as formal use cases rather than an Agile backlog — each one specified with an activity diagram and a sequence diagram. Written as stories, three representative examples:

"As a Registered User, I want to add a new holding to my portfolio, so I can track my investment performance accurately."

Given a Registered User is adding a new holding, when the entered stock symbol fails validation against the market data service, then an inline error is shown instead of saving.

"As a user, I want to search for a stock and view its price history with different chart types, so I can research before investing."

Given a user is researching a stock, when they change the time period or chart type, then the price history updates accordingly and can be compared against the S&P 500.

"As a Registered User, I want to view community discussion on a stock, so I can see other investors' insights before deciding."

Given a Registered User is on a stock's discussion page, when they like a post or submit a new discussion thread, then the interaction is tied to that stock and immediately visible to other users.
